# bffi-core

[![License: MIT](https://img.shields.io/badge/License-MIT-3DA639)](https://github.com/DotBlood/bffi-rs/blob/main/LICENSE)
[![Rust](https://img.shields.io/badge/Rust-1.98.0-DEA584?logo=rust&logoColor=white)](https://github.com/DotBlood/bffi-rs/blob/main/rust-toolchain.toml)

Foundation crate of [bffi-rs](https://github.com/DotBlood/bffi-rs/blob/main/README.md) - the Bun-only native
binding framework. It provides the low-level primitives that every other
`bffi-*` crate (`bffi-types`, `bffi-error`, `bffi-object`, `bffi-callback`,
…) builds on, and enforces the safety rules from
[docs/DESIGN.md](https://github.com/DotBlood/bffi-rs/blob/main/docs/DESIGN.md) §6.

**Status:** phase 0 (foundation) complete. No `extern "C"` functions live
here - the C ABI layer is generated by `bffi-macros` / `bffi-build` (P1/P2)
on top of these primitives.

## Contents

| Module       | Provides                                                               |
| ------------ | ---------------------------------------------------------------------- |
| [`handle`]   | Opaque [`Handle`] and [`TypeTag`] that cross the C ABI                 |
| [`table`]    | [`HandleTable<T>`] - generational arena owning objects as `Arc<T>`     |
| [`catalog`]  | [`Registry`] - process-wide routing of handles to typed tables         |
| [`error`]    | [`ErrorCode`], [`BffiError`] and the thread-local last-error transport |
| [`boundary`] | [`catch_panic`], [`run_extern_body`] and the [`bffi_extern!`] macro    |

Zero runtime dependencies (`std` only), no `unsafe` blocks, thread-safe.

## Why handles

Crossing the C ABI drops almost all Rust safety guarantees. Raw references,
`Box` or trait objects must never travel across it. Instead, Rust-side
objects live as `Arc<T>` inside a [`HandleTable`], and the foreign side only
ever sees an opaque 64-bit [`Handle`]:

```text
63        48 47            24 23             0
┌────────────┬────────────────┬────────────────┐
│  type tag  │   generation   │      index     │
│   16 bits  │     24 bits    │     24 bits    │
└────────────┴────────────────┴────────────────┘

u64 = (type_tag << 48) | (generation << 24) | index
```

- **Type tag** identifies the kind of object (and therefore the table that
  owns it). A handle presented to the wrong table is rejected.
- **Generation** makes staleness unambiguous: freeing a slot bumps its
  generation, so a stale handle can never resolve to a later occupant of
  the same slot (ABA protection). Slots that would wrap past the maximum
  generation are retired forever instead of reused.
- **Index** addresses the slot; capacity is bounded at 2^24 live objects
  per table.

The zero value is `Handle::NULL` and never resolves to an object.

## Type tag allocation

Tags are statically assigned ranges with one owner each; new ranges are
reserved by documenting them in `handle.rs`:

| Range             | Owner                             |
| ----------------- | --------------------------------- |
| `0x0000`          | null handle, never a valid object |
| `0x0001`–`0x00FF` | reserved for `bffi-core`          |
| `0x0100`–`0x01FF` | `bffi-object`                     |
| `0x0200`–`0x02FF` | `bffi-callback`                   |
| `0x0300`–`0x03FF` | `bffi-class`                      |
| `0x0400`–`0x7FFF` | future `bffi-*` crates            |
| `0x8000`–`0xFFFF` | user native modules               |

## Quick start

```rust
use std::sync::Arc;
use bffi_core::{HandleTable, Registry, TypeTag};

// A user-module type stored behind handles.
struct Session { id: u32 }

// User modules own tags in the 0x8000–0xFFFF range.
const SESSION: TypeTag = TypeTag(0x8001);

fn main() {
    // Per-module tables work standalone…
    let arena = HandleTable::<Session>::new(TypeTag(0x8002));
    let h = arena.insert(Arc::new(Session { id: 1 })).expect("room available");
    assert_eq!(arena.get(h).expect("live").id, 1);
    arena.remove(h);
    assert!(arena.get(h).is_none(), "removed handles stay invalid");

    // …or through the process-wide registry used by the C ABI layer.
    let registry = Registry::global();
    registry.declare::<Session>(SESSION).expect("declared once");
    let rh = registry.insert(SESSION, Arc::new(Session { id: 7 })).expect("room");
    assert!(registry.get_typed::<Session>(rh).is_some());
    assert!(registry.remove(rh));
}
```

The registry verifies both the tag and the requested type on every lookup,
so a handle of one kind can never be reinterpreted as another.

## Panics and the FFI boundary

Every `extern "C"` entry point must be thin, and a Rust panic must never
unwind into the Bun host. The policy (DESIGN §6.5):

| Build   | Behavior                                                               |
| ------- | ---------------------------------------------------------------------- |
| debug   | the panic escapes and aborts the process (easier debugging)            |
| release | the panic is caught and converted into `ErrorCode::Panic` + last error |

The [`bffi_extern!`] macro bakes this policy into a declaration; the
procedural `#[bffi]` attribute (`bffi-macros`, P1) will expand to the same
shape:

```rust
use bffi_core::{bffi_extern, error::ErrorCode};
use std::sync::atomic::{AtomicU32, Ordering};

static LAST_SUM: AtomicU32 = AtomicU32::new(0);

bffi_extern! {
    /// Adds two numbers and records the sum.
    pub extern "C" fn my_add(a: u32, b: u32) -> ErrorCode {
        LAST_SUM.store(a.wrapping_add(b), Ordering::Relaxed);
        ErrorCode::Ok
    }
}
```

Wrapped bodies return [`ErrorCode`] - the numeric status that crosses the
C ABI. Failures carry details through the thread-local last-error slot
(`set_last_error` / `take_last_error`), the same scheme as `errno` /
`sqlite3_errmsg`; the `bffi-error` crate (P0) will turn it into a JS
`Error`.

> **Note:** release profiles must keep `panic = "unwind"` (the workspace
> default). The shipped artifact is a library loaded into the Bun host
> process - abort-on-panic would kill Bun, which is exactly what the
> boundary exists to prevent.

## Safety properties

- **No `unsafe`** anywhere in the crate; the table and registry are built
  from `RwLock` + `Arc` alone.
- **Thread-safe by construction**: all operations take `&self`; reads take
  a shared lock, mutations an exclusive one. Locks poisoned by a panicking
  thread are recovered rather than propagated (documented trade-off: the
  reported live count may drift; lookups stay correct).
- **Errors are `#[non_exhaustive]`** so the set can grow without breaking
  downstream matches.
- **Bounded resource use**: at most 2^24 slots per table; exhausted tables
  return `TableError::Full` instead of growing unbounded.

## What does _not_ belong here

Per DESIGN §8–9 (one responsibility per crate):

| Concern                                                    | Home                        |
| ---------------------------------------------------------- | --------------------------- |
| Numbers / strings / buffers conversion, `unsafe_zero_copy` | `bffi-types`                |
| Mapping [`BffiError`] to a JS `Error`                      | `bffi-error`                |
| Object wrapping / lifetimes above the registry             | `bffi-object`               |
| Callback registration and marshalling                      | `bffi-callback`             |
| `#[bffi]` and C ABI generation                             | `bffi-macros`, `bffi-build` |

## Testing

```sh
cargo test -p bffi-core          # everything
cargo test -p bffi-core --doc    # documentation examples
```

Suites: unit tests per module, plus integration tests for the handle bit
layout (`tests/handle_layout.rs`), the FFI boundary and panic conversion
(`tests/boundary.rs`), and multi-threaded stress tests covering slot reuse,
ABA rejection and registry traffic (`tests/table_concurrency.rs`).
