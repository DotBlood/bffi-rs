# bffi-rs C ABI calling convention

> Canonical reference for every C ABI crossing in bffi-rs. The
> generators (`#[bffi]` in `bffi-macros`, `bffi_runtime_abi!()` in
> `bffi-build`, `#[bffi_class]` planned in `bffi-class`) implement
> exactly this contract; their READMEs link here instead of restating
> it. Sources of truth above this document: `docs/DESIGN.md` §6 and
> `AGENTS.md`.

**Status:** P2. Covers function shims (P1) and the runtime exports
(P2). Buffers as _parameters_, class method shims, and struct-by-value
/ cstring _returns_ are future work (see "Non-goals").

---

## 1. General shape

- Every export is `pub extern "C"`, `#[unsafe(no_mangle)]` (edition
  2024 attribute form), thin: it converts arguments, calls one Rust
  function, writes the result, returns the status.
- The C ABI cannot return `Result`. Failures cross as a numeric
  [`ErrorCode`] return; details travel through the thread-local
  last-error slot (`bffi_core::set_last_error`), which the JS side
  drains with `bffi_error_take_last` after observing a non-zero code.
- Symbol names are snake_case with the `bffi_` prefix; user function
  `foo` -> shim `bffi_foo`. Names must be unique process-wide (they are
  `#[no_mangle]`); a collision is a link error, reported by the linker.

## 2. Build profile policy (DESIGN §6.5)

| Build   | Body behavior                                                   |
| ------- | --------------------------------------------------------------- |
| debug   | runs bare; a panic escapes and aborts the process (easier debugging) |
| release | wrapped in `run_extern_body` (status returns) / `run_extern_body_or` (value returns): the panic becomes `ErrorCode::Panic` + a stored last error |

Both variants are generated under `#[cfg(debug_assertions)]` /
`#[cfg(not(debug_assertions))]` as two definitions of one symbol.

## 3. Parameters

| Rust type                  | C ABI shape                                | Notes |
| -------------------------- | ------------------------------------------ | ----- |
| `i8` `i16` `i32` `u8` `u16` `u32` `f32` `f64` `bool` | the primitive itself | by value |
| `i64` `u64`                | `i64` / `u64`                              | JS sees `bigint` |
| `Handle` (objects, buffers, callbacks) | `u64`                          | JS sees `bigint`; `0` = null |
| `&str`                     | `*const c_char`                            | NUL-terminated UTF-8 ("cstring"); validated by `bffi_types::str_view`, invalid UTF-8 -> `ErrorCode::InvalidUtf8` + last error |
| `String`, buffers, `Option`, `Vec`, structs | **not supported as parameters** | see Non-goals |

## 4. Returns

| Rust result                    | C ABI shape                                         | Notes |
| ------------------------------ | --------------------------------------------------- | ----- |
| `()`                           | `-> ErrorCode`                                      | no out-parameter |
| primitive / `i64` / `u64`      | `-> ErrorCode` + trailing out-param `__ret: *mut T` | null `__ret` -> `ErrorCode::NullPointer` (no UB) |
| `String`, `Vec<u8>`, `CopiedBuf`, `Option` of these | `-> u64` handle into the buffer table | JS reads via `bffi_buffer` / `bffi_buffer_length`, releases via `bffi_types_free`; `0` = failure (`Option::None` or table error) |
| `Result<T, E>`                 | like `T`; on `Err` returns `ErrorCode::DomainError` (13) | the error message is `E`'s `Display`, stored in the last error with `E` as the source |

The out-parameter always comes **after** the regular parameters and is
named `__ret` (`__`-prefix: reserved for generated code).

## 5. Runtime exports (generated by `bffi_runtime_abi!()`)

| Symbol                   | Signature               | Returns |
| ------------------------ | ----------------------- | ------- |
| `bffi_error_take_last`   | `() -> u64`             | handle of the drained last error (as a readable slot), `0` = none |
| `bffi_error_name`        | `(h: u64) -> u32`       | `1` = Error, `2` = TypeError, `3` = RangeError, `0` = invalid |
| `bffi_error_message_ptr` | `(h: u64) -> *const u8` | pointer to UTF-8 bytes, valid until `bffi_error_free` |
| `bffi_error_message_len` | `(h: u64) -> u64`       | byte length |
| `bffi_error_free`        | `(h: u64) -> u32`       | `ErrorCode` value: `0` = Ok, `4` = InvalidHandle |
| `bffi_buffer`            | `(h: u64) -> *const u8` | pointer to the bytes, valid until `bffi_types_free` |
| `bffi_buffer_length`     | `(h: u64) -> u64`       | byte length |
| `bffi_types_free`        | `(h: u64) -> u32`       | `ErrorCode` value: `0` = Ok, `4` = InvalidHandle |

Pointer lifetime: read synchronously, then free. Stale handles are
detected on the Rust side (generations); raw pointers are not
revalidated.

## 6. Status code table

| Code | ErrorCode          | JS constructor | Raised when |
| ---- | ------------------ | -------------- | ----------- |
| 0    | `Ok`               | -              | success     |
| 1    | `Error`            | Error          | unspecified failure |
| 2    | `Panic`            | Error          | caught panic (release path) |
| 3    | `NullHandle`       | Error          | null handle passed |
| 4    | `InvalidHandle`    | Error          | stale / foreign / unknown handle |
| 5    | `TableFull`        | Error          | handle table exhausted |
| 6    | `InvalidTag`       | Error          | unknown type tag |
| 7    | `InvalidUtf8`      | TypeError      | cstring parameter is not UTF-8 |
| 8    | `NumberOutOfRange` | RangeError     | number out of target range |
| 9    | `NullPointer`      | TypeError      | null out-parameter |
| 10   | `BufferTooSmall`   | RangeError     | caller buffer too small |
| 11   | `InvalidArgument`  | TypeError      | argument contract violated |
| 12   | `WrongThread`      | Error          | call from a non-JS thread that could not be marshalled |
| 13   | `DomainError`      | Error          | `Err` from a `Result<T, E>` return |

## 7. Type tag ranges

See the table in `crates/bffi-core/src/handle.rs` (`TypeTag` docs).
Today: `0x0100-0x01FF` bffi-object, `0x0200-0x02FF` bffi-callback,
`0x0300-0x03FF` bffi-class (reserved), `0x0400-0x04FF` bffi-build
(runtime tables: `0x0400` drained errors, `0x0401` transient buffers),
`0x8000-0xFFFF` user modules.

## 8. Non-goals (bun:ffi limitations)

- cstring **returns** (a Rust `&str`/`String` cannot be returned as a
  pointer into Rust memory the JS side would free differently);
  strings travel as buffer handles instead.
- Structures by value (parameters or returns).
- Buffers as direct parameters (a `ptr, len` parameter pair is a
  future candidate; the hand-written `example_echo_buffer` export in
  `examples/native` is the reference sketch).
