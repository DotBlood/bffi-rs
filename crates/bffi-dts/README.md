# bffi-dts

[![License: MIT](https://img.shields.io/badge/License-MIT-3DA639)](https://github.com/DotBlood/bffi-rs/blob/main/LICENSE)
[![Rust](https://img.shields.io/badge/Rust-1.98.0-DEA584?logo=rust&logoColor=white)](https://github.com/DotBlood/bffi-rs/blob/main/rust-toolchain.toml)

TypeScript declaration (`.d.ts`) generation crate of
[bffi-rs](https://github.com/DotBlood/bffi-rs/blob/main/README.md) - the
Bun-only native binding framework. Every exported native symbol ships with an
accurate declaration file from day one, per the "TS types" decision in
[docs/DESIGN.md](https://github.com/DotBlood/bffi-rs/blob/main/docs/DESIGN.md)
§7.

**Status:** P1 complete - a static IR (`ModuleDef` / `FunctionDef`) and a
deterministic renderer, with golden tests pinning the output bytes.
**ZERO dependencies**: the crate has no `[dependencies]` section at all.
Determinism is the whole point - same IR in, same bytes out. The `#[bffi]`
macro that auto-emits the descriptors arrives with `bffi-macros` (P2);
hand-written descriptors work today.

## Determinism contract

`render` is pure and never panics: the output depends only on the IR.

- a fixed two-line header: `// @generated by bffi-dts - do not edit.` then
  `// Source module: {name}`;
- no timestamps or version numbers are embedded;
- functions are emitted in IR (declaration) order;
- LF line endings throughout and exactly one trailing newline;
- JSDoc: no docs renders nothing, one doc line renders `/** line */`, two or
  more render a `/**` opening line, one ` * line` per doc line, and a ` */`
  closing line;
- each function renders as `export function name(param: type, ...): ret;`.

Re-rendering the same module always produces a byte-identical file, which is
what the golden tests pin.

## Sanitization

Names pass through [`sanitize`] before rendering, so the renderer can never
emit an invalid declaration. Validity follows the ASCII rule
`[A-Za-z_$][A-Za-z0-9_$]*` plus an ECMAScript reserved-word check (a
deliberate choice: determinism first). Valid names pass through unchanged
with no allocation; invalid, reserved, or empty names get a `_` prefix:

- `class` -> `_class`
- `delete` -> `_delete`
- `""` -> `_`

Sanitization is total and deterministic - it never fails and never panics.

## The export_name convention

Every `FunctionDef` carries `export_name = "bffi_" + js_name` - the C ABI
symbol the native library exports. The convention is what keeps the
declaration file aligned with the linked surface exactly: `bffi-build`
consumes `export_name` at build time (P2) to link the symbol, while `render`
never emits it into the `.d.ts` - JavaScript only ever sees `js_name`.

## Who produces the IR

Today: you do, by hand. Descriptors are plain `Copy` values over `&'static`
slices, so a module is just a `static` constant. From stage 4, the `#[bffi]`
macro emits the same descriptors (`bffi_meta_*::FUNCTION` consts) directly
from annotated Rust functions. Hand-written descriptors are not a fallback -
they are the P1 contract (criterion 6.2) that the macro output must match.

## Quick start

```rust
use bffi_dts::{AbiOut, AbiPrim, AbiSig, AbiType, FunctionDef, ModuleDef, ParamDef, TsType};

static PARAMS: &[ParamDef] = &[
    ParamDef { name: "a", ty: TsType::Number },
    ParamDef { name: "b", ty: TsType::Number },
];
static ABI_PARAMS: &[AbiType] = &[AbiType::U32, AbiType::U32];
static DOCS: &[&str] = &["Adds two numbers."];
static FNS: &[FunctionDef] = &[FunctionDef {
    js_name: "add",
    export_name: "bffi_add",
    docs: DOCS,
    params: PARAMS,
    ret: TsType::Number,
    abi: AbiSig {
        params: ABI_PARAMS,
        out: Some(AbiOut::Prim(AbiPrim::U32)),
    },
}];

let module = ModuleDef { name: "math", fns: FNS, classes: &[] };
let dts = bffi_dts::render(&module);
assert!(dts.contains("/** Adds two numbers. */"));
assert!(dts.contains("export function add(a: number, b: number): number;"));
```

## The ABI signature

Besides the TypeScript view, every function and method descriptor carries an
`AbiSig`: one `AbiType` per JS-visible parameter (`Cstring` for `&str`,
one `PtrLen` entry for `&[u8]`, exact widths for the primitives) plus the
out-parameter slot (`AbiOut::Prim(width)` or `AbiOut::Handle` for the shared
`u64` slot byte-carrying returns travel through). The `.d.ts` renderer ignores
it; loader-side tooling consumes it so the exact C ABI shapes never have to be
re-derived from the coarse `TsType`. Field getters carry their `export_name`
(`bffi_<class>_<field>_get`) and out slot the same way.

## What does _not_ belong here

Per DESIGN §8-9 (one responsibility per crate):

| Concern                        | Home            |
| ------------------------------ | --------------- |
| `#[bffi]` codegen              | `bffi-macros`   |
| Build-time integration / CLI   | `bffi-build`    |
| JS Error mapping               | `bffi-error`    |
| Object ownership               | `bffi-object`   |
| Callbacks                      | `bffi-callback` |

## Testing

```sh
cargo test -p bffi-dts          # everything
cargo test -p bffi-dts --doc    # documentation examples
```

Suites: unit tests for `ir` and `ident`, plus golden integration tests
(`tests/golden.rs`) covering the renderer - byte-exact fixtures
(`tests/golden/*.d.ts`) with LF normalization, a determinism check, and a
no-carriage-return guard. Textual comparisons
normalize `\r\n` back to `\n` (undoing any `core.autocrlf` effect on Windows
checkouts), a guard test asserts the committed golden files are LF-only, and
the repo-root `.gitattributes` forces `eol=lf` for `*.d.ts`. A determinism
test proves re-rendering each module is byte-identical.
