# @z2net/native-template (COPY ME)

**This directory is a TEMPLATE, never published as-is.** Copy it into
your own project (or your crate's repo), replace every
`@z2net/native-template` occurrence with your package name, and follow
the steps below. It is the reference implementation of pattern A
(napi-rs style distribution): the main package is pure JS; every
platform ships as its own npm package carrying the prebuilt binary.

## Layout

```
native-template/
├── package.json            # main pkg: exports + optionalDependencies (exact pins)
├── src/
│   ├── index.ts            # createNative(): resolve binary -> typed API
│   └── api.gen.ts          # GENERATED by `bffi codegen` (schema embedded)
├── scripts/
│   └── pack-platforms.ts   # assembles platform/ packages from a built binary
├── RELEASE.md              # release/publish workflow template
└── platform/               # GENERATED by pack-platforms (gitignored)
    ├── @scope/native-template-win32-x64-msvc/  { package.json, index.js, native.dll }
    ├── @scope/native-template-linux-x64-gnu/   { ..., libnative.so }
    └── @scope/native-template-darwin-aarch64/  { ..., libnative.dylib }
```

## Steps for your crate

1. **Rust side**: annotate exports with `#[bffi]` / `#[bffi_async]` /
   `#[bffi_class]`; in the crate root expand `bffi_runtime_abi!()`
   (and `bffi_callback_abi!()` / `bffi_async_abi!()` when used); build
   with `cargo build --release` (crate-type `cdylib`).
2. **JS side**: aggregate the descriptors into a `ModuleDef` and write
   the loader JSON (`bffi_build::loader_json::write_to_file`), then:

   ```sh
   bun bffi codegen js/bffi.api.json -o src/api.gen.ts
   ```

   Replace `--runtime` with `"@z2net/bffi-loader"` once published (this
   template keeps a relative import so it type-checks before
   publication).
3. **Pack the platforms** (after `cargo build --release`):

   ```sh
   bun scripts/pack-platforms.ts --src target/release/<your-lib>.dll --triple win32-x64-msvc
   bun scripts/pack-platforms.ts --src target/release/lib<your-lib>.so --triple linux-x64-gnu
   bun scripts/pack-platforms.ts --src target/release/lib<your-lib>.dylib --triple darwin-aarch64
   ```

4. **Consume**:

   ```ts
   import { createNative } from "./src/index.ts";
   const api = createNative();                 // resolves the platform package
   const api2 = createNative("./my.dll");      // or an explicit path
   ```

## Publishing (when ready)

See [RELEASE.md](./RELEASE.md): platform packages are published FIRST
(exact versions), then the main package. Until then the package stays
`private: true` and only `npm pack` dry-runs are expected.
